§1

How a session actually runs

You open it. It never opens you: nothing runs on a schedule at v1. It asks which mode, reads your log, and then it speaks first. What you write is always an answer to something the agent engineered from your own worst patterns.

The mechanism

Your log writes the prompt

A generic tutor asks how your weekend was. This one reads get_recent_errors(20), finds the pattern you fail most, and picks a question you cannot answer correctly without using that exact structure. Elicitation is targeted, so practice volume lands where the points are.

Where each mode fits in a week
Mon / Wed / Fri
Gespräch, 15 minutes. Turn by turn, one to three sentences per reply, roughly ten exchanges.
Tue / Thu
Aufgabe, 20 minutes. One full text, written under a timer, submitted once. This is the exam rehearsal.
Sunday
You run review.py. No conversation. It prints three patterns and next week’s focus.
Never
The agent contacts you first. That is a later extension, and the trigger is you starting to skip days.

§6

Thirteen categories, and no fourteenth

The model must pick from a closed list. Let it invent labels and you get "case", "Kasus" and "dative error" as three separate weaknesses. Anything you intend to count has to be constrained at write time.

§8

What it costs to run

Model calls scale with errors, not with sessions, because each correction triggers a tool call and another call to continue. Push the sliders until you leave the free tier. It takes some doing.

Assumes one model call per logged error plus one to close the turn, ~1,400 tokens in and ~260 out per call.
